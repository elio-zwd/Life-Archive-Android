# 已有笔记打开提速计划

确认日期：2026-10-23。目标版本：0.2.2。本文记录已确认的实施要求；实际检查结果见[阅读提速交接](../engineering/phase-1-reader-performance-handoff.md)。

## 已确认行为

- 阅读分为正文投影、首屏准备、屏外按需渲染。以保存的原文偏移定位，首屏不等待整篇公式、图表及附件。基于完整文档生成分块，保留脚注、表格、嵌套引用等上下文。
- 首屏公式、图表排版后展示；图片、媒体、PDF 允许稳定占位后局部填充。前后一屏预处理重内容，折叠内容展开后处理；同类公式/图表串行，附件最多两个并发任务。
- 局部更新通过原文锚点及屏幕偏移补偿位置，不重建整页或清除其他媒体、折叠及 PDF 状态。错误按块反馈并提供重试。
- 复用已核验的正文会话快照；首屏之后空闲预备编辑高亮，编辑时复用同一任务和结果。300 ms 草稿、800 ms 正文保存仍独立运行。

## 缓存约定

采用按需持久缓存，只为打开过的内容生成派生物，不进行全库预处理或建立 WebView 常驻池。

| 类型 | 容量上限 | 内容 |
| --- | --- | --- |
| 内存 | 32 MiB | 最近使用的阅读投影、公式/图表及布局数据 |
| 内部磁盘 | 256 MiB | HTML 投影、公式/图表 SVG、附件尺寸及布局信息 |
| 现有远程缓存 | 512 MiB | 手动加载或设置自动缓存的远程资源、网页副本 |

单条派生物不超过 8 MiB；超限仍正常阅读。按最近使用淘汰；普通重启后复用，清理或系统回收后自动重建。32 MiB 指应用管理的缓存数据，不是整个 App 或 WebView 的总内存上限。缓存失败不影响正文保存或正常阅读，缓存不进入备份。

文档缓存按资料库命名空间、身份/路径、正文摘要及投影版本区分；公式、图表和布局再包含渲染库版本、主题、字号、字体及宽度条件。每篇笔记独立投影，嵌入目标独立核验；缓存不保存展开后的整页、事件回调、PDF 画布或播放状态，也不复制整份媒体。

设置独立显示并清理阅读加速缓存。清理和资料库替换使旧任务失效，不允许旧任务落回缓存；缓存代次跨普通重启保留。

## 接口与验证

沿用十个模块：core:document 提供带原文范围的阅读投影；domain:notes 定义 ReaderCacheRepository；data:notes 实现缓存；app 装配；editor/settings 通过公开接口调用。缓存不是权威状态，不改变 Room v2、备份 v1 或正文事实来源。

JavaScript 只通过受限本地主页面消息提交派生物，核对来源、页面修订、代次、类型及大小；不支持消息能力时保留完整渲染。缓存命中仍清理 HTML/SVG，并重新绑定来源笔记及 SVG ID。

回归覆盖首屏、按需加载、原文定位、显示条件失效、缓存损坏/失败/淘汰、跨重启、清理并发、恢复换代、组合输入、高亮、保存与撤销。电脑、浏览器和目标机分别报告。

使用真实验收样例及配图、50 KiB/1 MiB、500 篇库、50 MiB PDF；每组至少 20 次，报告首次打开、同进程重开及进程重启后的 p50/p95、命中率和内存。目标机在 App 前台、库就绪时，样例/50 KiB 首屏首次 p95 ≤ 1 s、缓存重开 p95 ≤ 500 ms；1 MiB 独立报告，未测保持 NOT_VERIFIED。
