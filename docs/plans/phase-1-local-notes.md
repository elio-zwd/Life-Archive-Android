## 1. 目标与项目边界

- 只做 Android，明确不开发 iOS、Web 或桌面客户端。
- 面向个人使用，优先做到记录顺畅、资料易找、文件可用、保存可靠。
- 采用 Kotlin + Jetpack Compose 原生 Android 路线；已建立底座的固定版本见[工程交接](../engineering/bootstrap-handoff.md)，业务框架和编辑/渲染依赖仍在实际接入时验证。
- 开发环境面向 Windows 10 x64，Windows 命令使用 PowerShell 7（pwsh.exe）。
- 旧 App 数据库已经清空，本期不考虑旧数据库迁移；普通 Markdown 文件导入属于本期功能。
- 旧 UI 设计稿不再作为本期验收依据，重新确定配色、视觉层级和页面交互。
- 首页直接围绕笔记组织，不沿用原 App 的五舱功能结构。
- 本期专注本 App，不接入 AI，不改造见域，不建设两款 App 共用模块。

## 3. Obsidian 文档兼容范围

“完整语法”以 Obsidian 官方内置文档语法为基准，不等于复刻 Obsidian 全部应用功能，也不自动包含第三方插件自定义语法或执行环境。

本期覆盖：

- 标准 Markdown：标题、段落、强调、列表、任务清单、引用、分隔线、链接、图片、代码块、表格等。
- YAML 属性、标签、别名；编辑保存时保留不认识的属性字段。
- 双链及显示别名、标题引用、块标识与块引用、同笔记和跨笔记跳转。
- 笔记、章节、块及图片、音视频、PDF 等官方支持的文件嵌入语法与对应展示。
- Callout、折叠提示块、脚注、行内脚注、高亮、注释、删除线等扩展写法。
- 行内及块级公式、Mermaid 图表、官方支持范围内的 HTML 格式。
- 图片尺寸、嵌入参数、附件路径解析等与文档可用性直接相关的行为。

实现时依据官方文档建立逐项兼容样例，验证显示、编辑保存、跳转和往返保真。尚未完成渲染适配的语法必须保留原文，不能在保存时被删除；仅保留原文不等于该项兼容已经完成。

实时预览编辑未达标时，可以采用源码编辑与阅读预览；这一调整只影响编辑形式，一期已列入范围的阅读展示、嵌入和引用能力仍须完成。范围内语法仅保留源码属于开发中的临时状态，不能作为完整交付依据。

## 4. 存储约定

- 笔记本对应文件夹，笔记正文对应 UTF-8 Markdown 文件，图片与附件独立保存。
- 顶部笔记名对应不含 `.md` 的文件名，点击后执行实际重命名；正文 H1/H2 和 YAML `title` 独立，任何一方的修改均不隐式同步到另外两方。
- 文件是笔记正文的事实来源；Room 用于可重建的搜索索引、列表缓存和应用状态，避免维护两份相互独立的正文。
- 需要随笔记带走的标签、别名等信息，采用 Obsidian 兼容的属性或文档语法。
- 文件名和路径应兼顾 Windows 与 Android，处理非法字符、保留名及同目录重名等冲突，不覆盖已有文件。文件移动、重命名默认维护可识别内部链接、相关引用和索引；失败时明确反馈并恢复一致状态。
- 添加图片和附件后，应由 App 管理保存，不依赖外部原文件永久存在。
- 笔记文件应能交给电脑 Obsidian 使用；本期不实现电脑连接或同步流程。

## 5. 简单可靠的数据保护

面向个人使用，备份恢复只安排必要机制：文件格式及版本检查、操作确认、明确的成功或失败提示，以及实际恢复验证。

本期不规划复杂的多层校验、密钥体系、差异合并、云同步或后台自动备份。保存失败保留草稿，普通删除进入回收站，完整备份必须实际能够恢复。

## 6. 验收重点

- 返回列表、切换笔记和重新打开 App 后，已保存内容正确。
- 保存失败时保留当前草稿，不误报成功。
- 中文输入、选中文字、长文编辑、滚动和键盘遮挡正常。
- 重启后图片和附件仍能打开，移动或重命名后的链接仍可用。
- 默认新建、取消命名、快速记录和重名处理符合交互约定；文件名、正文标题、YAML `title` 不发生隐式同步，重命名或移动失败不能误报成功。
- 标题及正文搜索、筛选和排序能处理实际使用规模；性能目标在样板阶段结合使用量确定。
- 用代表性文档验证 Obsidian 与 App 之间的文件往返，正文、属性、链接和附件信息不因保存丢失。
- 对官方内置文档语法逐项验证，不能仅凭所选渲染库声称完全兼容。
- 完整备份实际恢复出笔记、分类和附件，不以“导出成功”代替恢复验收。
- 在 Android 上验证实际交互与视觉，不以桌面预览或编译成功代替体验验收。

## 7. 编辑器与视觉决策

编辑器交互和视觉方向已记录在[《第一期：编辑器交互与视觉决策》](phase-1-editor-visual-decisions.md)：

- 以实时预览编辑作为目标默认编辑模式，保留完整源码编辑与阅读模式。
- 视觉采用 B 方向：中性浅灰白背景、深灰正文、克制蓝色强调，并提供深灰而非纯黑的深色模式。
- 默认新建先输入笔记名，确认创建文件成功后进入正文编辑并弹出键盘；快速记录可提供独立入口，以唯一默认名称直接开始编辑。打开已有笔记默认进入阅读状态、恢复上次阅读位置且不自动弹出键盘。
- 已接入一期功能版后，按已认可设计优化首页、编辑与阅读 UI，其他临时页面保留；本轮在用户确认规格的模拟器检查布局，中文输入、光标/选区、长文、键盘和保存可靠性仍分别验证。
- 只有样板通过基础交互验收后，才将实时预览作为一期正式默认编辑体验；若输入稳定性不达标，一期先采用源码编辑与阅读预览，阅读兼容范围不随之缩减。
- 链接文字与其他蓝色强调用途分开定义，并按实际背景检查对比度；参考色及计算记录见视觉决策文档。

具体编辑器依赖、底层实现和版本选择在样板验证后确定。以上是已确认的产品目标与验收边界，不代表功能已经实现。
