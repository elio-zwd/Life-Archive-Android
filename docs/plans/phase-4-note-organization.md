# 第四期优化：笔记分类与整理制度

确认日期：2026-11-09。状态：已确认实施计划；实际实现和检查结果以[分类整理交接](../engineering/note-organization-handoff.md)为准，设备验收单独记录。本项独立属于第四期；[电脑阅读显示与修改差异](phase-4-pc-reading.md)继续独立记录。

## 1. 目标与边界

App 与电脑共用主题、类型、层级标签制度。电脑固定 `D:\Obsidian\人生档案\`，App 仍管理私有库，由现有手动同步传递相同结构。首次历史整理必须预览、分批确认；不自动搬动真实笔记。

不接入模型、不自动读正文分类、不设置强制 AI 参与标记。取消讨论初期“来源在前、独立 AI 内容第三类”的设想，以本次主题优先规则为准。电脑 AI 深入讨论、归纳、优化属于外部工具使用流程，三期文档补充用法，不扩大成内置 AI。

## 2. 分类制度

实际路径为 `主题/类型/笔记.md`。初始主题依次为职业发展、沟通表达、效率工具、健康管理、饮食烹饪、休闲生活、学习研究、生活事务；允许新增、改名、合并，不预建细分类。

| 类型 | 规则 |
| --- | --- |
| 个人笔记 | 自己的记录、思考，以及经判断采纳整理形成的成果；可以使用 AI 辅助 |
| 视频摘记 | 以记录视频为主要目的，可附自己的评论 |
| 待整理 | 主题或类型未确定；其他独立资料暂不强制归入前两类 |

全局待整理中，已知类型可保存在 `待整理/个人笔记/` 或 `待整理/视频摘记/`，保留已知信息；类型未知直接在待整理下。文件夹是主归属事实来源，不再维护一套相互矛盾的分类 YAML。历史非标准路径先显示待整理，确认前原地保留。

每篇只有一个主主题和实际位置，可有多个跨主题标签。标签最多三级，如 `职业发展/面试/自我介绍`，允许一二级；细标签不生成目录、增删不移动文件。父标签包含下级，多选默认全部符合，可切换任一符合。人工可新增标签，外来新标签先确认采用、映射或不采用；历史标签未确认不批量改写或截断层级。

主题、标签改名或合并前展示涉及目录、笔记和标签。新名称已存在时合并，不覆盖同名文件；改变主题同步维护相关标签前缀和链接。文件名、正文标题、YAML title 保持独立。

## 3. App 流程

- 默认同页按主题分组、可折叠，待整理在前，主题按初始顺序，新主题追加。空组不展开；保留卡片、封面、置顶和其他排序。组内默认真实内容修改时间倒序，未知置后，同时间按名称。
- 可切换按标签分组；同篇可显示于多个组，明确提示，不复制文件。主题、类型和多标签分别筛选，标签可跨主题查询。
- 主题内新建个人笔记沿用当前主题；全局快速记录默认个人笔记、主题待整理；视频入口默认视频摘记；通用粘贴不猜类型。分类未完成不阻止保存。
- 收录与文件导入均先展示外来标签，允许改为已有标签或不采用。导入先进入待整理子目录，保留相对结构和附件引用，不把收录时间当原始写作时间。
- 首页“更多 → 分类与整理”支持多选、统一设置主题／类型／可选属性标签／核实后的时间。单篇管理菜单提供同一入口。
- 预览包含原位置、目标位置、标签变化、时间确认和涉及链接。确认前不写；确认时再核对版本、草稿和目标占用。受阻项跳过，其余有效项一次可恢复提交；磁盘失败回滚有效批次，不误报成功。重建保留 ViewModel 内待确认内容和单任务状态。
- 历史建议只取标准目录、明确属性和已有标签与主题的准确对应。多候选列出，不按顺序猜选；不读标题或正文推断类型。可另用电脑 AI 协助分析，最终仍由用户在 App 确认。

## 4. 身份与内容时间

现有库在讨论时核对为 62 篇、62 个唯一 ID，只读核对不是迁移执行。App 新建首次落盘写 `life_archive_id`；电脑新增继续由同步补齐，受控 AI 新建也生成新 ID。修改、移动、改名保留；独立新副本换 ID。封面、置顶、阅读位置保留。

YAML 使用 `life_archive_created_at`（真实首次写录）和 `life_archive_updated_at`（内容修改）。已知到秒使用带时区 ISO 8601，只知日期保存日期精度，未知省略。原有 `date` 不自动改名或认定用途。

App 原生新建以首次成功保存为写录时间；导入、粘贴、接收同步不推断原始写作时间。历史 App 创建／活动记录仅是候选，用户核实后才回填。此前电脑文件时间集中在同步落盘的数秒内，不能回填为历史写作时间。

正文和有内容含义的属性改变更新内容时间；同步、移动、改名、分类、标签、补 ID、维护链接不刷新。同步仍按哈希和共同基线判断，不依赖时间。普通 Obsidian 编辑若未带可靠新时间，标记待确认，不把旧时间冒充当前修改时间。

所有字段只做定点处理，保留未知 YAML、注释、正文、BOM、换行。重复／无效 ID、异常时间或无法安全定位的 YAML 明确拒绝相关写入，不猜测覆盖。

## 5. 工程和验证门槛

沿用十二个模块：core:document 处理安全元数据与双方契约，domain:notes 提供查询、内容保存、整理／分类预览与条件提交；data:notes 复用 StorageGate、链接维护、文件事务恢复及备份。新增状态显式迁移，内部活动时间不冒充内容时间。App 显式组装，feature 不依赖 data。

电脑提供 PowerShell 7 编辑完成工具，验证同任务首次备份、ID、内容变化和写入条件，再维护时间；帮助、预演、重复调用和失败退出可验证。不增加分类界面、Obsidian 插件或编辑监控。

`verifyNoteOrganization` 无设备入口须通过相关单测、Robolectric／Compose、架构、Lint、Debug APK 和三期同步回归；PC 须通过工具、契约、相关回归、前端和浏览器服务冒烟。2026-11-09 实施中用户明确暂不需要 PC 安装包，因此本次取消安装包构建、安装版冒烟与安装包交付，不作为完成门槛；源码浏览器服务和脚本继续验证。真实 Kotlin 客户端、真实存储与 PC HTTP 完成整理后双向往返；500 篇合成笔记记录整理耗时。所有自动化只用临时资料。

交付安装产物、版本、SHA-256、检查结果、用法、限制和[独立真机清单](../testing/note-organization-manual-acceptance.md)。小米 14 Ultra 的覆盖安装、分组筛选、历史整理、实际同步与视觉在用户验证前均为 `NOT_VERIFIED`。
