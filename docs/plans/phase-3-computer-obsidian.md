# 第三期：简化双向同步与 AI 修改前备份

确认日期：2026-11-04。原第二期后置，本期先行；本文件描述已确认范围，实际交付及检查结果见[三期交接](../engineering/phase-3-sync-handoff.md)。

## 目标与范围

- Android 与现有 `D:\My_Elio\life-archive-pc` 在同一局域网双向同步，由手机手动发起，PC 软件接收。
- 电脑目录为 `D:\Obsidian\人生档案\`，直接保存普通 Markdown、笔记本目录与本地附件，供 Obsidian 阅读和编辑；不随 PC 当前浏览的档案库切换。
- 同步全部正常笔记本及附件；不传输 App 设置、草稿、阅读缓存、Git、Obsidian 配置和修改前副本。
- 两端新增、编辑、删除、笔记改名及移动均纳入本期。身份识别曾短暂移到第四期，用户最新决定重新纳入第三期，采用 YAML ID 简化实现。
- 本期不增加云同步、后台自动同步、AI 调用、正文自动合并或 App 内版本对比。第四期另含独立的[分类整理与内容时间](phase-4-note-organization.md)，电脑阅读显示与修改差异仍只记录方向。

## 同步规则

- 在 YAML 定点补齐 `life_archive_id` UUID。已有有效值保留；手机现有笔记优先沿用内部 ID。保留其他 YAML、注释、BOM、换行及正文；不安全的 YAML、无效或重复 ID 报错并跳过相关笔记。
- 通过 ID 关联笔记，改名／移动保留手机封面、置顶及阅读位置。附件按相对路径识别；附件移动是删除旧路径加新增新路径。接收端不再另做链接改写。
- 对比共同基线、手机和电脑的 ID、路径及内容 SHA-256。单端变化传到另一端；两端不同变化、删除与修改并发、同路径不同笔记均需选择手机版、电脑版或暂时跳过，其他独立文件继续同步。
- 删除进入对端可恢复回收站，不自动清空。手机笔记沿用原回收站，附件增加同步回收站；PC 文件保留在 `.life-archive/trash/`，可由面板恢复。
- 初次连接、重新配对或完整恢复后重新核对资料，不以单端缺失推断历史删除。根目录不可用、扫描失败不得当作空库。
- 条件写入、校验和确认成功后才更新对应基线；失败不冒充成功，重试不重复创建笔记。
- 同步前处理手机草稿，暂停 Obsidian／AI 编辑。版本再次变化时停止相关文件操作，不建设外部编辑器锁定机制。

## 接入和备份

- 首次在 PC 初始化目录并生成配对码，手机填写电脑显示的地址及配对码。配对码短期、一次有效，后续使用独立设备凭据，可在 PC 撤销。
- 新同步替换旧手机协议和旧云轮询；不自动迁移、删除旧资料，不改动其他无关 PC 功能。
- `domain:sync` 定义规则和公开接口；`data:sync` 实现通信、配置及基线；`data:notes` 实现笔记域专用同步接口，统一存储门锁、条件写入和恢复。feature 不依赖 data 实现。
- 同步配置和同步附件回收站有独立备份参与者；设备凭据及基线不导出。兼容缺少新增可选数据域的历史备份，恢复后清除凭据并作废基线。
- PC 初始化 Git，不自动暂存、提交或推送；`.life-archive/` 加入 `.gitignore`，其中保存辅助状态、回收站和 `修改前副本/`。
- 每轮 Codex 等 AI 任务修改前，PowerShell 7 脚本备份本轮准备修改的相对文件列表。相同任务标识补充新文件，已有副本不覆盖；新增文件登记原先不存在。失败返回非零退出码并停止修改。
- 资料目录提供 `AGENTS.md` 调用约定；不拦截任意外部软件写入，不自动清理副本。

## 电脑 AI 协作使用（四期补充）

2026-11-09 电脑 AI 使用约定补充：三期同步目录和修改前备份供外部 AI 深入讨论、归纳多篇和优化原文使用，不是内置 AI。每轮先备份全部修改／新增路径，失败停止；单篇修改保留 ID，多篇综合默认保留原文、新建成果并用新 ID、链接参考笔记。观点不同写明原文与新增思考，不把 AI 意见伪装成视频观点。形成个人理解的成果归个人笔记，用途未定先待整理；不自动删除或提交 Git，不与手机同步同时编辑。四期完成工具在编辑后核对备份并维护真实内容时间，未知不猜测；工具说明见[分类交接](../engineering/note-organization-handoff.md)。本段是协作用法及后续工具入口，不追溯声称三期原版已实现内容时间。

## 初步交付门槛

全部满足后才称“初步交付完成，可开始真机验证”：

1. Android 架构检查、单测、相关 Robolectric／Compose、Lint、`verifyPhaseOne` 和 Debug APK 构建通过；`verifyPhaseThree` 汇总新增检查。
2. PC 新同步单测、契约测试、相关原有回归、前端及 Win10 x64 安装包构建通过，服务和面板完成电脑侧冒烟检查。
3. 真实 Kotlin 客户端、真实笔记存储与 PC HTTP 接口，在临时合成库完成双向协议往返；覆盖冲突、删除、身份、改名移动、草稿、恢复、断线及故障。
4. 脚本帮助、预演及中文路径、逐任务补备份、失败和 Git 忽略检查通过。
5. 使用约 500 篇笔记、200 MiB 附件和单个 50 MiB 文件验证，记录耗时与传输量，无变化不重传正文／附件；电脑结果不代表手机性能。
6. 交付 APK、PC 安装包、版本与 SHA-256、检查结果、使用说明、限制及独立真机清单。

全程自动化只使用临时合成资料，不同步真实笔记，不安装或操作手机。小米 14 Ultra 的安装、局域网连接、同步交互、阅读与视觉保持 `NOT_VERIFIED`，由用户随后实测。
