# 0.2.4 编辑器回车与长文输入修复交接

日期：2026-10-24。基于 `d8c813b` 的 main，版本 0.2.4／versionCode 6；按用户后续授权分类本地提交，不推送、不操作手机。需求及默认行为见[工具栏计划补充](../plans/phase-1-editor-toolbar.md)，完整工具用法沿用[0.2.3 交接](phase-1-toolbar-handoff.md)。源码与实验实时预览仍共享同一正文、选区和撤销历史，没有新增模块、依赖、迁移或持久设置。

## 1. 修复及使用行为

| 问题 | 本次行为 |
| --- | --- |
| 先选有序列表，再加引用，输入后回车闪退 | 不再假设引用一定在列表前面。`1. > 内容` 续为 `2. > `；无序、待办和多层交错组合使用同一识别逻辑。64 种三层容器组合均检查合法补丁。 |
| 空的混合容器再次回车 | 每次退出最内一层；例如 `1. > > ` → `1. > ` → `1. ` → 正文。新待办为未勾选；有序编号只递增当前项，不重排后文。 |
| 长文点击空白、移动光标或重新弹键盘触发重复计算 | 正文修订与选区／组合范围／焦点分开。复用同一不可变正文快照，输出变换按区间查询样式及标记，不在显示回调内差分全文。 |
| 高亮尚未就绪时输入控件等待或被卸载 | 立即建立输入控件和输入连接，高亮后台补齐；空笔记刚产生正文时不丢失焦点。 |
| 每次输入都启动完整解析，列表回车从文首扫描 | 初次高亮正常准备，后续局部投影优先、完整解析延迟 200 ms；回车复用行状态检查点，只补扫脏区。草稿 300 ms、正文 800 ms 的计时独立运行。 |
| 续写隔离撤销时把未改字符误记为脏区 | 对 ChangeList 的局部边界去除未变字符，保留原标记和高亮；不为此扫描全文。续写仍为一次输入事务和一个撤销步骤。 |
| 在空笔记粘贴 CRLF 后回车 | 从变化片段识别 CRLF，后续续写保留换行类型，不产生双 CR；多行粘贴不触发自动续写。 |

九位有序编号到达 `999999999`、容器深度达到识别上限，或保护状态无法安全确认时，保留普通换行。输入回调最多补扫 8192 个 UTF-16 代码单元；超长单行、远处大修改后的索引尚未就绪等情况可能暂时不补前缀，但不阻止输入、不吞换行。YAML、围栏代码、缩进代码、HTML 和表格等位置继续保持普通换行。选区替换、候选词确认和多行粘贴不误续写。

## 2. 实现与维护入口

- `core:document` 的 `MarkdownContinuation` 保留 String 入口，增加 CharSequence／ContinuationContext 入口；行状态不可变，前缀识别不再复制整行尾部。构造补丁之后、写输入缓冲区之前验证区间与光标，识别异常只放弃自动增强，不回滚用户输入。
- `EditorSession.content` 每次正文变化建立一个修订快照，供保存、解析、工具栏与阅读复用。程序化修改统一经过会话的 `edit`；显式撤销／重做只在历史动作中核对一次差分。不得重新引入显示回调里的全文转换或正文回写。
- `EditorContent` 索引带最大结束位置的区间树，能查询跨窗口的外层引用。待解析的修改按已知增量映射所需范围；标记被改动时不隐藏，不依据重复字符猜测修改身份。会话最多保留 256 条增量元数据，超出可追溯范围时不应用旧标记，等待新投影。
- ViewModel 在后台准备投影索引与回车检查点，并在公开前核对正文修订。修改后仅沿未变前缀复用检查点；过期结果、关闭会话及资料替换不能安装旧索引。页面 ViewModel 清理时结束会话、释放派生索引。
- `EditorEngine` 接口与 Markdown／Repository 权威来源不变；源码与实时预览高亮继续保留，长文沿用光标附近窗口。阅读、备份和存储协议不变。

输入事务使用项目已固定的 Compose Foundation 1.10.5 公开 API，不读取内部组合状态、不修改原生撤销历史；依据见 [TextFieldBuffer](https://developer.android.com/reference/kotlin/androidx/compose/foundation/text/input/TextFieldBuffer) 与 [Compose 文本输入](https://developer.android.com/develop/ui/compose/text/user-input)。
