## 2026-10-31 阅读重开兼容修复

用户反馈“创建验收样例”首次可读，第二次打开报 `filter(...).at is not a function`。定位为 System WebView 缺少 `Array.prototype.at`：首次偏移为 0 时跳过定位分支，保存非零阅读位置后重开，首屏任务选择与正文滚动恢复会调用该方法。此异常发生在阅读脚本中，不表示 Markdown 正文损坏。

阅读脚本已用基础数组操作替换四处 `.at(-1)`，覆盖首屏任务定位、正文滚动恢复、嵌入标题文字回退和附件扩展名识别。没有修改正文、存储或缓存格式。浏览器回归通过显式移除 `Array.prototype.at` 检查首次打开、带位置重开、原页刷新，以及嵌入标题和图片／PDF／音视频附件；修复前可复现同一报错。入口仍为 `testReader`，电脑回归不能代替用户当前 WebView 的设备复验。

本次 `testReader :app:assembleDebug checkArchitecture --console=plain` 通过，浏览器共 40 项检查通过；`git diff --check` 通过。Debug APK 仍输出到 `app/build/outputs/apk/debug/app-debug.apk`，未安装到设备。本次未重跑完整 `verifyPhaseOne`、Lint 或真机交互／视觉验收；下方 0.2.2 的验证数字保留历史含义。

## 实现

- 根笔记使用已核验的 ReaderSnapshot，不重复读取正文；嵌入笔记独立读取核验。core:document 生成 HTML、原文范围、块锚点与正文摘要，旧 render 入口保留。
- ReaderWork 先准备当前原文位置的首屏公式/图表，再展示；图片/媒体/PDF 稳定占位后填充。前后一屏调度，折叠内容展开后处理；公式与图表各自串行，附件共享两个并发槽。
- 附件并发槽保持到图片解码、音视频元数据或 PDF 指定页准备完成；图片实际尺寸与旧占位不符时按解码结果修正。PDF.js 同时设置 disableAutoFetch/disableStream，按范围读取当前页所需内容，不预取整份文件。
- 局部变更保持原文锚点与像素偏移；保存状态、滚动和单资源更新不重建整页。首屏完成后才空闲预备当前笔记的编辑高亮，保存观察仍独立。
- ReaderCacheRepository 由 domain:notes 定义、data:notes 实现，app 装配到阅读及设置。内存 32 MiB、磁盘 256 MiB、单条 8 MiB，LRU 淘汰；默认远程缓存仍为独立的 512 MiB。
- 缓存目录为 app cacheDir 下的 reader-results，不参加备份。二进制记录带代次、标识、长度及 SHA-256 校验；原子替换、损坏回退，普通重启保留命名空间，清理/恢复前换代。32 MiB 是缓存数据上限，不是 App 或 WebView 总内存。
- 文档投影按正文摘要/身份/路径/投影版本缓存；SVG 按库版本及显示条件缓存。布局包括主题、字号、字体、像素比及宽度。嵌入保持独立投影，缓存不固化外部目标或媒体会话。
- 缓存消息只接受 HTTPS 本地主页面，核对页面修订、类型、大小及代次；HTML 不允许通过网页消息写入。缓存 SVG 与首次渲染同样清理，重新绑定 ID、内部引用与所属笔记链接。消        息能力不可用时跳过网页派生物写盘，阅读能力保留。
