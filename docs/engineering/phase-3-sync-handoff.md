# 三期同步实现与初步交付

日期：2026-11-04。范围依据：[第三期计划](../plans/phase-3-computer-obsidian.md)。

## 实现与接口

- Android `0.3.0` / versionCode `9`；PC `1.1.0`。设置页“电脑同步”提供配对、连接测试、手动同步、进度、提示和冲突选择。
- `NotesSyncRepository` 负责清单、条件复制／匹配／提交及附件回收；`SyncRepository` 负责状态、配对与同步。`domain:sync` 不依赖 Android；`data:sync` 对 `data:notes` 的依赖仅用于真实存储集成测试。
- YAML `life_archive_id` 是可携带身份；匹配原笔记时保留内部 ID、封面、置顶和阅读位置。首轮定点补字段，保留其他 YAML、正文、BOM 与换行；非法／重复 ID 跳过，不猜测覆盖。
- 清单交换 ID／路径、SHA-256、字节数；共同基线判方向，无变化不传文件内容。条件提交前再次检查，网络不持笔记域门锁。
- “测试连接”只读握手，不扫描或补写笔记 ID；正式同步才进行 ID 补齐。
- 同路径不同 ID 先选择，落败文件进入回收站；一般冲突选手机版、电脑版或跳过。目录结构／大小写冲突先改为跨端合法路径再重试，不自动删除占用目录。
- PC 固定绑定 `D:\Obsidian\人生档案`，不随当前浏览档案库切换。旧云配置加载、轮询和旧 `/api/sync` 协议路由已退出服务装配；不迁移、不删除旧资料。历史工具源码及独立测试不代表旧同步仍在运行。
- PC `.life-archive/` 被 Git 忽略且不参与同步，其中有操作记录、回收站和 AI 修改前副本。设备凭据哈希在 PC 用户配置目录；Android 凭据由 Keystore 加密保存，不导出、不写正文或日志。

## 使用

1. 在新版 PC 软件登录并打开“手机同步”，点击“初始化同步目录”，再“生成配对码”。初始化创建目录、Git、忽略规则、脚本和编辑约定，不自动提交。
2. 手机设置 → 电脑同步，填写实际 Wi-Fi／有线局域网地址和配对码。不要使用电脑的 `127.0.0.1` 或 VPN 虚拟地址。
3. 保存手机草稿，暂停 Obsidian／AI 编辑，点击“立即同步”。冲突可选一端或跳过；跳过后保留两端原样，下次仍重新核对。
4. 在 Obsidian 打开目标目录。保护 `life_archive_id`；复制为新笔记时删除新副本的该字段，让同步分配新 ID。
5. 手机笔记在原回收站恢复；手机附件在“电脑同步”的附件回收站恢复。PC 在同步面板的“同步回收站”恢复。路径被占用时先处理占用，不覆盖现有文件。

每轮 AI 修改前，用 PowerShell 7 在资料目录执行：

```powershell
& '.\.life-archive\Backup-NotesBeforeEdit.ps1' -Root (Get-Location).Path -TaskId '20261104-整理一' -Paths @('工作/记录.md', '准备新建.md')
```

同轮追加对象用相同 TaskId，下一轮用新 TaskId。副本在 `.life-archive/修改前副本/<TaskId>/files/`；清单记录原先不存在的新文件。失败必须停止修改；脚本检查实际 Git 忽略规则。本机制依赖调用约定，不拦截绕开脚本的外部写入。

## 恢复兼容

外层备份仍为 v1，notes 快照 format=3，状态库 v3；新增 `notes-sync-trash` 和 `sync` 可选历史参与者。旧备份缺少新增域时显式重置，未知域继续拒绝。新版备份由新版 App 恢复；旧 App 不认识新增参与者。

完整恢复清除凭据与基线，须重新配对、重新核对，不能用旧基线推断删除。本地操作沿用原存储恢复；PC 以 prepared／committed 记录区分回滚与已提交重试。
