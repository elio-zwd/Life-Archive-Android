# 0.2.5 首页列表性能修复交接

日期：2026-10-24。版本 0.2.5／versionCode 7，保持 main，按用户后续授权分类本地提交，不推送、不操作设备。针对用户报告的首页上下滑动明显掉帧，修复代码中可确认的重复工作，并检查同类的筛选、刷新及列表位置问题。没有新增模块、依赖、持久缓存、迁移或正文格式变更。

## 检查与修复

| 代码中发现的问题 | 修复与边界 |
| --- | --- |
| 每个笔记条目组合时用 `find` 从头扫描详情列表，越靠后越贵；反复进入屏幕反复查找。 | 一份快照一次 O(n) 关联，显示值预先准备；条目按 ID 使用详情。行模型只持有不可变字符串，可跳过无关状态引起的重组。 |
| 页头、筛选、提示与笔记未区分 `contentType`，提示使用位置标识。 | 为各类内容声明复用类型及稳定 key，笔记独立命名空间；保持同一笔记在刷新、提示增删和排序后的滚动锚点。 |
| 文件名和标签可无限换行，极端数据会放大条目测量和高度。 | 名称、路径和标签摘要最多两行；完整标签保留在原文及详情，属性标签管理仍读取原始详情，正文和数据未截断。 |
| 标签／笔记本菜单用 `forEach` 一次创建全部选项。 | 超过 20 项时用限高的懒列表选择框；短菜单沿用原交互。筛选选项按快照复用。 |
| 无搜索词的列表刷新也为每篇构造包含全文的新字符串。 | 空查询跳过搜索字符串构建；非空查询分别匹配元数据与缓存正文，不复制全文拼接。多词可跨字段命中，正文偏移语义保持。 |
| 相同筛选仍启动查询；分析准备循环未主动响应取消。 | 忽略完全相同的筛选值，准备分析时逐篇检查取消；保留 200 ms 防抖及旧回执保护。 |

列表行回调身份保持稳定，执行时读取最新回调和当前详情，避免进度变化导致整行无效重组或回调继续捕获旧状态。刷新期间打开和管理入口统一禁用。

存储访问已通过 `StorageGate` 在 IO 线程执行，本轮未发现主线程直接文件读取。查询仍会读取索引正文并复用现有分析缓存；本轮不把它描述成增量索引查询，也不新增缓存层。只有用户实际执行新筛选、数据变更或重建才会刷新，单纯滚动不查询存储。

按同类风险还检查了其他滚动入口：设置和插入面板是固定规模内容，编辑器菜单为固定选项；正式阅读使用已有 WebView 适配。未把历史 Compose 阅读样板替换成新的阅读方案。复用与按需组合依据为 [Compose 官方列表文档](https://developer.android.com/develop/ui/compose/lists#content-type)，真机性能对比须使用一致构建类型，不能混比 Debug 与发布构建。

## 小米 14 Ultra 验收

以下项目保持 **NOT_VERIFIED**；本轮不连接手机、不安装或清理数据。APK 通过系统覆盖更新手动安装，保留原有资料。若要做前后量化对比，先采集现有版本；记录系统版本、刷新率、构建类型、热状态及是否正在索引。

1. 使用约 500 篇的合成测试库，包含中英混合标题、深层目录、长名称、多标签和索引待更新笔记。索引完成后，从顶部连续滑至底部再返回，重复至少 20 轮，记录长停顿和帧时间；冷／热列表、索引中分别记录。
2. 滑到中间后触发筛选／置顶／重建引起的列表更新，核对同一可见笔记与位置，不误打开或管理别的资料；筛选后原笔记已消失时按新的列表自然定位。
3. 分别打开少量与 500 项标签／笔记本选择，连续上下滑动并选末项；关闭和重开、重复选择、切排序、进入／退出回收站均正确。
4. 长文件名和多标签条目保持摘要高度，管理界面仍可读取全部属性标签，正文标签在原文核对。浅／深主题、大字号与返回首页分别核对。

桌面 Robolectric 的访问次数、组合与锚点断言不能换算成手机 FPS。只有目标机实测后才能确认用户报告的掉帧是否完全消除。
